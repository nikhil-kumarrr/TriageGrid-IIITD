# Security Policy

## Reporting a Vulnerability

Security is paramount in healthcare technologies and autonomous triage agents. If you discover a security vulnerability or sensitive data issue within **TriageGrid**, please notify the maintainers privately rather than opening a public issue.

- **Email**: Send details to the project maintainers or open a private security advisory on GitHub.
- **Response Time**: We aim to acknowledge reports within 48 hours and provide a remediation timeline.

## Scope & Prototype Boundaries

TriageGrid was built as an academic and hackathon prototype for the **CareCompass Challenge (IIIT-Delhi)**.

Key security practices implemented in this codebase:
- **No Client Secrets**: API keys (`GEMINI_API_KEY`, `GROK_API_KEY`, `TINYFISH_API_KEY`) stay strictly server-side in `.env` and are never exposed in frontend builds.
- **Synthetic Data Isolation**: All data in this repository is 100% synthetic (generated by Sanocare Tech Innovations). No real Protected Health Information (PHI) or Personally Identifiable Information (PII) is processed.
- **SQL Injection Prevention**: All queries use parameterized statements with transactional concurrency controls (`BEGIN IMMEDIATE`).
- **Emergency Safeguards**: Deterministic red-flag lexical screeners bypass non-urgent appointment workflows for acute symptoms.

For detailed architecture constraints and production deployment prerequisites, see [docs/SECURITY.md](docs/SECURITY.md).
